# 物业管理系统 — 项目说明与需求分析

## 1. 选题背景与研究意义

随着城市化进程加快，住宅小区的规模不断扩大，物业管理的对象日益复杂。传统物业管理工作依赖人工登记、纸质台账与电话沟通，存在以下突出问题：

- 收费管理靠手工登记，账目容易出错，业主缴费情况难以实时掌握；
- 报修、投诉依赖电话与纸质工单，处理进度不透明，业主无法追踪；
- 设备巡检依靠纸质记录，检查结果难以追溯，异常发现后缺乏闭环处理；
- 业主与物业之间信息不对称，公告、缴费、报修进度等信息传递滞后。

本课题设计并实现一套**基于 Spring Boot + Vue 的社区物业管理系统**，将小区基础信息、收费管理、报修处理、投诉建议、设备巡检、公告通知等业务线上化，为物业管理员、财务人员、维修工、巡检员和业主提供统一的信息化工作平台，提升物业管理效率与服务质量。

## 2. 系统目标

本系统面向小区物业管理场景，实现以下目标：

1. **基础数据信息化**：统一管理楼栋、房屋、业主、车位、设备等基础档案；
2. **收费流程闭环**：物业管理员发布收费项目并生成待缴费账单，财务线下收款后确认，业主可随时查看自己的缴费记录；
3. **报修流程透明**：业主或巡检员提交报修，管理员派单，维修工接单处理，报修人确认评价，全流程可追踪；
4. **投诉处理规范**：任何人均可投诉，管理员给出解决方案，投诉人确认并评价；
5. **巡检管理闭环**：管理员制定巡检计划并指定巡检员，系统按周期生成巡检任务，巡检员打卡记录结果，异常自动转报修，维修完成后自动标记已处理；
6. **实时消息推送**：基于 WebSocket 将工单状态变更、收费通知等实时推送给相关人员，列表数据自动刷新；
7. **权限精细控制**：基于 RBAC 的菜单/按钮级权限，不同角色只能看到并操作职责范围内的功能与数据。

## 3. 用户角色分析

系统共设计 6 类角色：

| 角色 | 角色标识 | 职责 |
|------|----------|------|
| 超级管理员 | admin | 系统最高权限，负责系统配置与用户管理 |
| 物业管理员 | property_admin | 社区日常业务管理：基础档案维护、报修派单、投诉处理、巡检计划制定等 |
| 业主 | owner | 线上查看房屋/车位、缴费记录、提交报修与投诉、确认评价 |
| 维修工 | repair_worker | 接单、处理报修工单、申报消费事项 |
| 巡检员 | inspector | 接收巡检任务、打卡填写巡检记录、异常一键报修 |
| 财务 | finance | 收费记录确认（线下收款）、消费事项审核 |

### 3.1 业主需求

- 查看自己的楼栋、房屋、车位信息；
- 查看自己的物业费账单并了解欠费情况；
- 提交报修工单，查看处理进度，结单后确认并评价；
- 提交投诉，查看处理结果，确认后评价；
- 查看物业公告与费用支出公示（消费事项）。

### 3.2 物业管理员需求

- 维护楼栋、房屋、业主、车位、设备等基础档案；
- 制定巡检计划并指定巡检员，发布收费项目；
- 报修派单、投诉受理与回复、公告发布；
- 查看各业务统计与待办事项。

### 3.3 财务人员需求

- 查看待缴费账单，线下收款后确认入账（记录实缴金额与备注）；
- 审核维修工申报的消费事项，审核通过后对业主公示。

### 3.4 维修工需求

- 接单、处理报修工单并结单；
- 结单时可申报维修消费事项；
- 查看与自己相关的报修与消费事项。

### 3.5 巡检员需求

- 接收巡检计划生成的巡检任务；
- 按周期打卡填写巡检结果（正常/异常）；
- 异常记录一键生成报修工单；
- 查看设备台账与设备记录。

## 4. 功能需求概述

| 模块 | 核心功能 |
|------|----------|
| 系统管理 | 用户管理、角色管理、菜单/权限分配 |
| 社区管理 | 楼栋、房屋、业主、车位档案维护 |
| 费用管理 | 收费项目管理、收费通知、缴费记录确认、消费事项审核公示 |
| 报修管理 | 报修提交、派单、接单、结单、评价、一键报修 |
| 投诉建议 | 投诉提交、受理、处理、回复、确认、评价 |
| 设备管理 | 设备分类、设备台账、设备记录汇总（只读） |
| 巡检管理 | 巡检计划、按周期生成任务、二维打卡记录、异常转报修 |
| 公告通知 | 公告发布、下架、置顶、定时发布 |
| 统计分析 | 维修、设备、人员、费用、投诉、巡检分模块统计与图表 |
| 首页工作台 | 按身份展示待办事项数量、最新公告 |
| 实时推送 | WebSocket 消息推送与列表自动刷新 |

## 5. 非功能需求

- **安全性**：BCrypt 密码加密、JWT 无状态认证、菜单/按钮级权限校验、接口级权限拦截；
- **可用性**：统一响应格式与全局异常处理，页面友好提示；
- **实时性**：关键业务状态变更通过 WebSocket 实时通知，列表自动刷新；
- **可维护性**：后端按业务模块分层，前端按模块组织，初始化脚本固化权限配置；
- **数据一致性**：业务操作使用事务管理，核心记录（设备记录、巡检修改）留痕。
