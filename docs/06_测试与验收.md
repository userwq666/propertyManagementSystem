## 3. 核心业务链路测试用例

### 3.1 报修全流程

1. 业主 zhouwei 提交报修（选择房屋）；
2. 维修工 chenjie 收到"新报修"推送，列表出现该工单；
3. 管理员 admin 派单给 chenjie（或 chenjie 直接接单）；
4. 业主收到"报修已接单"推送；
5. chenjie 结单，填写处理内容与消费金额；业主收到"报修结单"推送；
6. zhouwei 确认并评价（1-5 分）；chenjie 收到"报修已评价"推送；
7. 报修状态变为"已完成"，若关联设备则设备状态恢复"正常"。

### 3.2 收费全流程

1. 管理员 admin 新增收费项目（物业费，单价 3 元/㎡，范围全体）；
2. 发布项目：按房屋面积自动生成待缴费账单，同步生成收费通知并广播；
3. 业主 zhouwei 首页待办出现"待缴物业费"，列表可见账单；
4. 财务确认缴费（实缴金额=应收，备注可选）；
5. 业主收到"缴费确认"推送，账单状态变为"已缴费"。

### 3.3 巡检闭环

1. 管理员 admin 新增巡检计划（每日，设备：电梯，巡检员：zhouan）；
2. 次日定时任务生成巡检记录，zhouan 收到"新巡检任务"推送；
3. zhouan 在二维矩阵点击对应日期单元格，填写"异常"与异常描述；
4. 管理员收到"巡检异常"推送，待办出现"巡检异常待处理"；
5. zhouan 一键生成报修单；
6. 维修工处理并结单后，巡检记录单元格显示"已处理"；
7. 管理员修改已打卡记录时必须填写原因，修改记录留痕可查。

### 3.4 权限验证

1. 使用各角色账号登录，侧边菜单仅显示已授权菜单；
2. 未授权按钮不显示（`v-permission`）；
3. 直接调用未授权接口返回 403；
4. 业主无法看到他人房屋、车位、账单、工单。

## 5. 已知边界与说明

- 收费采用线下支付，平台只负责记录，不涉及第三方支付；
- 巡检打卡单元格仅显示到今天为止的有效周期，未来日期不生成；
- 设备记录为只读汇总，删除巡检计划/设备不影响历史记录展示；
