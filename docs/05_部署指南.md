# 物业管理系统 — 部署指南

## 1. 环境要求

| 软件 | 版本要求 | 说明 |
|------|----------|------|
| JDK | 17+ | 后端运行环境 |
| MySQL | 8.0+ | 数据库 |
| Maven | 3.8+ | 后端构建（可选，项目含 Maven Wrapper） |
| Node.js | 18+ | 前端构建（如需重新构建前端） |

## 2. 数据库准备

### 2.1 方式一：自动初始化（推荐）

1. 启动 MySQL 并创建数据库：

```sql
CREATE DATABASE IF NOT EXISTS property_management_system
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

2. 修改 `src/main/resources/application.properties` 中的数据库账号密码：

```properties
spring.datasource.username=root
spring.datasource.password=123456
```

3. 启动应用。`DatabaseInitializer` 会自动按顺序执行 `src/main/resources/sql/` 下的初始化脚本（建表、初始化角色/账号/菜单权限），并记录已执行版本，重复启动不会重复执行。

### 2.2 方式二：手动初始化

```bash
mysql -u root -p property_management_system < src/main/resources/sql/00_init.sql
mysql -u root -p property_management_system < src/main/resources/sql/01_system.sql
mysql -u root -p property_management_system < src/main/resources/sql/02_community.sql
mysql -u root -p property_management_system < src/main/resources/sql/03_fee.sql
mysql -u root -p property_management_system < src/main/resources/sql/04_repair.sql
mysql -u root -p property_management_system < src/main/resources/sql/05_complaint.sql
mysql -u root -p property_management_system < src/main/resources/sql/06_equipment.sql
mysql -u root -p property_management_system < src/main/resources/sql/07_inspection.sql
mysql -u root -p property_management_system < src/main/resources/sql/08_announcement.sql
```

## 3. 后端构建与运行

### 3.1 编译打包

```bash
# 方式一：使用系统 Maven
mvn clean package -DskipTests

# 方式二：使用 Maven Wrapper
./mvnw clean package -DskipTests
```

打包产物：`target/propertyManagementSystem-0.0.1-SNAPSHOT.jar`（已内置前端静态资源，单 JAR 部署）。

### 3.2 运行

```bash
java -jar target/propertyManagementSystem-0.0.1-SNAPSHOT.jar
```

- 服务地址：`http://localhost:8080`
- 停止服务：`Ctrl+C` 或 `taskkill /PID <进程号> /F`（Windows）

### 3.3 修改 JWT 密钥（生产必改）

```properties
jwt.secret=请替换为至少32位的随机字符串
jwt.expiration=86400000
```

## 4. 前端开发与构建

### 4.1 开发模式

```bash
cd frontend
npm install
npm run dev
```

- 开发地址：`http://localhost:5173`
- Vite 已配置代理：`/api` 与 `/ws` 转发到 `http://localhost:8080`，开发时需先启动后端

### 4.2 构建前端

```bash
cd frontend
npm run build
```

构建产物输出到 `src/main/resources/static/`（Vite 配置 `emptyOutDir: true`，自动清理旧产物），随后重新打包后端 JAR 即可部署。

## 6. 常见问题

**Q1：启动报错 "Unknown database 'property_management_system'"**

先手动创建数据库，再启动应用（见 2.1）。

**Q2：登录提示"未登录或Token已过期"**

确认请求头携带 `Authorization: Bearer <token>`；Token 默认有效期 24 小时，过期后重新登录。

**Q3：前端开发时接口 404**

确认后端已启动且监听 8080 端口；Vite 代理 `/api` 指向 `http://localhost:8080`。

**Q4：重复执行初始化脚本是否会冲突？**

不会。应用启动时 `DatabaseInitializer` 会记录已执行的初始化版本，避免重复执行；手动执行脚本前请先清空库。

**Q5：权限配置修改后需要重启吗？**

不需要。角色-菜单权限通过"系统管理 → 角色管理 → 菜单分配"修改后即时生效（重新登录加载最新权限）。

## 7. 生产环境建议

1. 修改数据库密码、JWT 密钥、默认账号密码；
2. 关闭 MyBatis 调试日志（`mybatis-plus.configuration.log-impl` 改为 `org.apache.ibatis.logging.slf4j.Slf4jImpl`）；
3. 数据库定期备份；
4. 若前后端分离部署，可将前端构建产物交由 Nginx 托管，并将 `/api`、`/ws` 反向代理到后端服务。
